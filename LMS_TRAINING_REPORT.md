## Что обучено

Модель не использует готовые открытые веса и не выполняет свободное посимвольное
декодирование:

1. Собственный `LmsHashEncoder` превращает вопрос и контекст в 1024 признака,
   включая структурные признаки LMS.
2. Собственная MLP-сеть выбирает один из 10 типов задач.
3. Вторая собственная сеть ранжирует факты внутри переданного контекста.
4. Безопасный декодер собирает ответ из контекстного факта и фиксированной
   формулировки. Поэтому ошибка не превращается в случайный набор букв.

Типы задач: прямой ответ по контексту, сводка, уточнение неоднозначности,
отсутствующий факт без интернет-догадки, навигация, атрибуция источника,
конфликт источников, административная эскалация, отказ от prompt injection и
явный запрос на веб-поиск.

## Подключение к API

Активный checkpoint загружается автоматически из
`model_artifacts/reliable_lms/lms.pt`. Дополнительно загружается локальный
индекс `model_artifacts/reliable_lms/knowledge_index.json`: `23 702` уникальные
группы контекста и `28 233` уникальные пары после удаления точных дублей.

По умолчанию `POST /generate` использует `response_mode=auto`. Он сначала
проверяет, относится ли вопрос к подтверждённому веб-каталогу, затем пытается
выбрать один контекст из локального LMS-индекса и только после этого вызывает
LMS-policy и fact-ranker.

Это не меняет честную оценку checkpoint: строгий test по-прежнему измеряет
модель на непересекающихся context-группах. Индекс является локальным
справочным слоем продукта и не используется для заявления новой метрики модели.

Если индекс находит единственный подтверждённый вариант, ответ содержит
`intent`, `confidence`, `context_used`, `source` и версию LMS-модели. Если
одинаковая формулировка встречается с несколькими разными значениями, API
возвращает уточнение и не выбирает случайный процент. После принятого ответа
контекст сохраняется в SQLite только для follow-up того же диалога.

Маршрут также содержит локальный смысловой слой до выбора контекста. Он не
переобучает checkpoint и не добавляет готовых ответов: распознаёт тему вопроса
и словоформу названия курса, затем сужает кандидатов. Поэтому фразы «какой
результат нужен, чтобы зачли обучение?» и «какой проходной балл?» используют
один тип правила, а follow-up о пересдаче не теряет уже подтверждённый контекст.
При конфликте данных этот слой сообщает понятную тему уточнения, но не меняет
запрет на случайный выбор факта.

Проверка готовности: `GET http://127.0.0.1:8000/health`. В ней должны быть
`lms_model_ready=true`, `lms_model_version=lms-context-policy-v2.0` и
`lms_knowledge_ready=true`.

Явный `response_mode=lms` с `lms_context` сохранён для внешних API-интеграций,
которые уже имеют собственный проверенный контекст. Браузерный интерфейс его не
использует.

### Проверка через браузерный чат

В `web_client/index.html` оставлено одно поле ввода. Оно всегда отправляет
`response_mode=auto`: пользователь пишет вопрос обычной фразой, без
переключения чата и без поля `lms_context`. Если для ответа нужны отличительные
данные, чат просит написать их следующим сообщением; подтверждённый материал
затем используется для коротких follow-up.

## Что осталось на следующем цикле

Текущий результат закрывает безопасный базовый этап обучения на LMS-контексте, но
не делает модель универсальным собеседником. Следующий цикл можно направить на
диалоговую память именно поверх LMS-состояния, контролируемое использование
результатов `/search`, расширение реальных (не только синтетических) сценариев и
производственный API-gateway. Свободное диалоговое обучение нужно начинать только
после отдельной приёмки качества, а не добавлением похожих реплик вслепую.
