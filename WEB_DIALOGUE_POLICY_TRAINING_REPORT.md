# Обучение web-dialogue-policy v1.0

Дата: 2026-09-13.

## Задача

`web-dialogue-policy-v1.0` — это небольшая собственная сеть, которая не пишет
ответ и не ищет информацию сама. Она оценивает только текущую пользовательскую
реплику и выдаёт одну из пяти политик: `must_browse`, `should_browse`,
`may_browse`, `must_not_browse` или `insufficient_context`.

В API положительное решение доступно лишь для `must_browse` и `should_browse`
при достаточной уверенности. Поэтому эта сеть не может заменить погодный
маршрут, локальное время, явный запрос пользователя или большой проверенный
`internet-router-v1.0`; она только добавляет осторожный дополнительный сигнал.

## Данные и границы

- Архив: `dialogue_web_training_seed_v1.zip` с SHA-256 `8144C848C2E8EE78CA6EE1A7868B795A991278513A1A50D3F13440BFD7F7BEAD`.
- Split: `140 / 30 / 30`; разбиение не менялось и прошло аудит без пересечений.
- В признаки вошли только `conversation.role=user` и целевая метка `browse_label`.
- Готовый ответ, system-подсказки, tool-сообщения, evidence, поисковые запросы и ссылки исключены.
- Код `validate_package.py` внутри ZIP не выполнялся.

## Архитектура и обучение

Собственные словесные, биграммные и символьные признаки → `EmbeddingBag` →
MLP `32 → 32 → 5`. Готовые открытые модели не загружались. Словарь строился
только по train, seed равен `42`; лучшей стала эпоха `10` по validation loss.

Validation выбрала консервативные пороги:

- confidence не ниже `0.85`;
- разрыв между двумя лучшими классами не ниже `0.30`;
- покрытие словаря не ниже `0.20`.

## Ограничение

Эти цифры не означают, что ИИ уже умеет вести человеческий разговор на любую
тему. Набор мал и синтетичен. Полезный результат этого обучения — более
аккуратный автоматический выбор момента, когда стоит обратиться к источникам,
а не создание новой свободной языковой модели. Качество самого веб-ответа
по-прежнему обеспечивают проверка источников и существующие специализированные
маршруты, в особенности погодный.
