# Контроль многостраничных сканов

29.10.2026. Семь оригинальных учебных PDF, 21 растровая страница без текстового
слоя. Все предметы и правила вымышлены. Файлы и spec.json изготовлены до правок
ядра. Повторная генерация поверх существующего набора запрещена; SHA256 в spec.

Проверяется перенос одной строки через три страницы, новая редакция последней
части этой строки, неверный номер продолжения и отсутствие последней страницы.
Отдельный четырёхстраничный файл содержит новые строки с повторённой шапкой.
Ещё два файла проверяют две сноски на разных страницах и чужую область сноски.

12 основных и 3 отложенных ожидания заданы вручную. Ожидаемые ответы не читаются
из OCR и не передаются поисковому ядру. Отложенный вопрос с двумя одновременно
действующими, противоречащими исключениями должен дать conflict.
Начальный результат: 3/12. Конечный: 12/12 и 3/3. Ошибку проверяющего кода
«2 календарных» внутри «12 календарных» исправили границей числа; сами
ожидания и PDF не менялись. В исходных ответах ошибочно перечислялись оба
исключения даже при явно отрицательных условиях.

Все 21 страницы отрендерены Poppler, проверены на шести контактных листах:
.runtime/closed-search-lab-20261028/multipage-rendered/contact-1.png … contact-6.png.

На сайте 3040 положительные документы доступны сотрудникам; новая конфликтующая
редакция и повреждённые варианты доступны только тестовому администратору.
В нагрузочном изолированном ядре используются выбранные документы: одинаковое
имя учебного товара в разных наборах не означает одинаковый регламент.

Воспроизведение из корня проекта:

```powershell
$env:OPENBLAS_NUM_THREADS='1'
$env:OMP_NUM_THREADS='1'
.\.venv\Scripts\python.exe -X utf8 -m evaluation.closed_search.multipage_probe
.\.venv\Scripts\python.exe -X utf8 -m evaluation.closed_search.multipage_probe --holdout
node evaluation/closed_search/multipage_http.cjs
node evaluation/closed_search/multipage_revisions.cjs
```

Для последовательных HTTP-прогонов учитывать лимит 30 вопросов на профиль
за 5 минут. Не отключать ограничение ради теста. После аварийного прерывания
проверка редакций допускает --recover: сверяются имя, права и байты временного
файла, удаляется только собственная запись lab_multipage_revision_probe.

Область поддержки ограничена явными маркерами продолжения и прямоугольными
ячейками с одной строкой шапки. Реальные неразмеченные переносы, сложные
многоуровневые шапки через границу листа и рукописные дополнения этим набором
не подтверждены.
