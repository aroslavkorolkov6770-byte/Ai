# Отложенная проверка веб-диалога

## Назначение

Этот набор измеряет, умеет ли собственная модель использовать предыдущую реплику при ответе на уточняющий вопрос. Файл `training_data/web_followup_eval.jsonl` не подключается к обучению и содержит 12 новых сценариев, или 24 уникальных текста начальных и уточняющих вопросов.

Перед проверкой выполнена сверка с web-корпусом: точных совпадений вопросов с обучающими данными — `0`.

## Методика

Для каждого сценария API получает начальный вопрос, затем повторный вопрос с тем же `conversation_id`. В первом прогоне контекст включён (`use_conversation_context=true`), во втором используется отдельный диалог с тем же начальным вопросом, но контекст отключён. В обоих случаях база знаний отключена (`use_knowledge_base=false`), поэтому измеряется только генерация модели.

Сравнение выполнено на активном checkpoint `tiny-gru-bpe-web-v1.3-dialogue` через локальный API `http://127.0.0.1:8000`.

## Результаты

| Режим | Точные follow-up-ответы | Среднее сходство |
|---|---:|---:|
| С контекстом | `0/12` | `0.2261` |
| Без контекста | `0/12` | `0.2260` |

- API подтвердил `context_used=true` в `12/12` случаях.
- В 9 случаях текст с контекстом имел более высокое мягкое сходство, в 3 — более низкое.
- Разница средних значений составила только `+0.0001`, поэтому считать навык диалога сформированным нельзя.
- Сгенерированные ответы остаются фрагментарными и иногда содержат искажённые технические слова.

## Вывод

Память диалога подключена технически и передаётся в модель, но маленький checkpoint пока не умеет надёжно извлекать из неё нужный объект или действие. Следующий этап — расширить и разнообразить отдельные диалоговые train-примеры, а после нового обучения повторить эту же отложенную проверку без изменения test-набора.
