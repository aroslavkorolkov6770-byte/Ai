# Brain v3 — протокол ручной semantic-проверки OASST1

Дата: 24 сентября 2026 года.

## Зачем нужен этот этап

Очередь `evaluation/results/oasst1-semantic-review-queue-v0.4/` содержит 104
metadata-only candidate IDs из 368 отобранных записей уже лицензированного
OASST1. Она заранее исключает восемь полных диалогов, где пользователь явно
отклоняет предыдущий ответ или прямо повторяет невыполненную просьбу. Их topic labels
получены эвристикой, а не являются разметкой качества. Нельзя превращать эти
ID в training material автоматически: у конкретного диалога могут оказаться
неестественный язык, плохой follow-up, ложная память, небезопасный совет или
лишняя ссылка.

`evaluation/oasst1_human_review.py` и отдельный local browser screen делают
проверку воспроизводимой:

- исходный текст одного диалога показывается только по явной локальной команде
  в терминале либо в отдельном loopback-only окне review;
- в decision ledger записываются только ID, SHA-256, split, verdict, короткие
  reason codes, роль reviewer и время;
- ни одна реплика не попадает в Markdown summary, decision JSONL, staging,
  active manifest или API;
- даже полностью заполненный review ledger не разрешает training или promotion.

## Что проверяет reviewer

Для каждого ID reviewer читает целый диалог и отвечает на четыре вопроса:

1. Русский язык естественный и без явных переводных/шаблонных артефактов?
2. Follow-up учитывает предыдущую реплику, а не отвечает случайно?
3. Ответ уместен и полезен для вопроса?
4. Нет ли личных данных, ложной памяти, нежелательной ссылки, опасного совета,
   legacy identity/capability фразы или иной причины исключить пример?

`approved` можно поставить только при всех четырёх положительных кодах:
`natural_russian`, `coherent_follow_up`, `relevant_response` и
`no_reviewer_detected_risk`. Для `rejected` выбирается хотя бы один
стандартизированный код причины; свободный текст намеренно не хранится.

## Локальные команды

### Удобный браузерный экран

Для обычной проверки без команд терминала запустите двойным щелчком
`start_oasst1_review.bat`, затем откройте:

```text
http://127.0.0.1:8011/
```

Экран работает отдельно от чата на порту `8000`, слушает только
`127.0.0.1` и не открывает внешний доступ. Он показывает ровно один
непроверенный диалог, позволяет пропустить его без записи, а при нажатии
`Одобрить` или `Отклонить` использует тот же metadata-only ledger, что и CLI.
Не запускайте одновременно несколько review-серверов или параллельные CLI
команды с записью verdict: один reviewer должен работать с одной очередью
последовательно.

Порядок показа детерминированно чередует primary topics и доступные split’ы,
поэтому ранняя проверка даёт широкий срез, а не случайную серию одинаковых
диалогов. Это влияет только на навигацию: candidate ID, текст, split, queue и
правила одобрения остаются неизменными.

Внутри уже выбранной группы topic/split экран может раньше показать запись с
техническим сигналом для внимательного чтения: длинной репликой ассистента,
коротким уточнением пользователя после ответа, ссылкой, контактом или
повторяющейся assistant-репликой. Это **не** verdict и не причина отклонения:
сигнал не меняет candidate, не записывается в ledger и не заменяет полное
чтение диалога человеком. Он нужен только чтобы reviewer внимательнее проверил
связность, уместность и возможный риск.

Нажатие `Одобрить` добавляет все четыре обязательных positive criteria.
`Отклонить` требует выбрать хотя бы одну фиксированную причину. Текст диалога
не записывается в browser storage, summary или decision JSONL.

Для защиты от случайного одобрения кнопка `Одобрить` остаётся недоступной,
пока reviewer явно не отметит все четыре условия после полного чтения
диалога. Local review endpoint дополнительно отклоняет попытку `approved` без
этого подтверждения. Это не автоматическая оценка: флажки может отметить
только человек, который прочитал конкретный диалог; для `rejected` по-прежнему
нужна хотя бы одна явная причина.

### Альтернатива: терминал

Показать ровно один candidate в локальном терминале, не создавая файлов:

```powershell
.\.venv\Scripts\python.exe -m evaluation.oasst1_human_review `
  --show-id oasst1.ru.0273a3425a14118b5b1f1ad6c169
```

Записать решение `approved` после полного просмотра:

```powershell
.\.venv\Scripts\python.exe -m evaluation.oasst1_human_review `
  --record-id oasst1.ru.0273a3425a14118b5b1f1ad6c169 `
  --decision approved `
  --reason-code natural_russian `
  --reason-code coherent_follow_up `
  --reason-code relevant_response `
  --reason-code no_reviewer_detected_risk
```

После одной или нескольких проверок создать новый metadata-only summary:

```powershell
.\.venv\Scripts\python.exe -m evaluation.oasst1_human_review `
  --summary-out evaluation\results\oasst1-semantic-human-review-v0.1
```

По умолчанию ledger находится в
`data/brain_v3/reviews/oasst1-semantic-review-decisions-v0.1.jsonl`. Скрипт
запрещает выход за controlled roots и не перезаписывает versioned summary.

## Граница следующего этапа

После полного review нужен отдельный immutable candidate только из разрешённых
записей, затем schema/risk audit, duplicate preflight, coverage audit и новая
ручная quality-проверка. Только все эти gate вместе могут вернуть вопрос к
обучению собственной модели с нуля. GitHub, веса и работающий API этим
протоколом не затрагиваются.
