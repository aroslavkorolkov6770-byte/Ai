обычное общение от прикладного запроса, а готовый безопасный текст для

## Экспериментальная свободная генерация

```powershell
python -m ai_core.train --epochs 3 --architecture gru --tokenizer bpe --tokenizer-vocab-size 512 --model-version local-gru-bpe-experiment
```

Для текущей основной темы используйте воспроизводимый запуск:

```powershell
python -m ai_core.train --epochs 70 --batch-size 32 --architecture gru --tokenizer bpe --tokenizer-vocab-size 256 --embed-dim 64 --layers 1 --dropout 0.10 --topic web --model-version local-web-experiment
```

После этого старого вида обучения появятся `model_artifacts/tokenizer.json`, `model_artifacts/tiny_transformer.pt` и `model_artifacts/training_metrics.json`.
В `training_metrics.json` также записывается лучшая эпоха по валидационной ошибке.

Параметр `--architecture` принимает `gru` или `transformer`, `--tokenizer` — `bpe` или `character`, а `--topic` — `all`, `web`, `python`, `data`, `system`, `math` или `other`. Размер сети задаётся параметрами `--embed-dim` и `--layers`. Все варианты модели и токенизатора реализованы внутри проекта и обучаются с нуля. Перед новым экспериментом нужно скопировать текущие три артефакта в отдельную папку `model_artifacts/versions/`, потому что обучение заменяет активные файлы.

При выборе `--topic web` к 115 подходящим строкам исходного набора добавляются 163 записи из `training_data/web_foundation.jsonl`. Исходный `dataset.jsonl` остаётся неизменным.

`POST /generate` по умолчанию использует `response_mode=auto`. В этом
режиме API распознаёт актуальные внешние вопросы, для погоды выбирает быстрый
структурированный источник, а для известных локальных тем использует собственный
QA- и диалоговый маршрут. Он не выбирает и не читает LMS-контекст автоматически.
Обычные реплики вроде приветствия, благодарности, просьбы обсудить мысль или
сообщения о затруднении получают нормальный разговорный ответ без упоминаний
старой технической темы. Вопрос о факте не перехватывается этим слоем: он идёт
в QA или контролируемый поиск.
Параметры `max_tokens`, `temperature`, `top_k` и beam search влияют только на
явно выбранный `response_mode=experimental`.

В браузерном чате теперь одно поле ввода: не нужно переключать чат или
вставлять технический контекст. История этого диалога хранится локально в SQLite
и помогает понимать короткие продолжения, но не используется как источник
внешнего факта. Старый изолированный `response_mode=lms` сохранён только для
обратной совместимости внешнего API и никогда не выбирается браузерным чатом.

Если в текущем разговоре написать, что ответы нужны короче или подробнее,
следующая обычная реплика подстроится под это пожелание. Более новая просьба в
самом вопросе важнее старой настройки. Это не отдельный профиль: предпочтение
действует только внутри текущего conversation_id и не переносится в новый чат.

Внизу чата доступен голосовой режим. Нажмите кнопку микрофона, произнесите
одну фразу и дождитесь паузы: браузер отправит распознанный текст в тот же чат.
Отдельный переключатель «Озвучивание» читает ответ вслух только после явного
включения. Для ответа используется единственный локальный голос `IVONA 2
Tatyana OEM`: браузер получает временный WAV от loopback API, а не выбирает
случайный голос из списка Windows и не отправляет текст в облачный TTS.

Исходный текст и WAV существуют только во временной папке на время синтеза,
после чего WAV читается в память и временная папка удаляется. Аудио и
расшифровка не попадают в SQLite, а в `localStorage` остаётся только состояние
переключателя озвучивания. Если локальная IVONA или воспроизведение временно
недоступны, текстовый чат остаётся рабочим и показывает понятное сообщение.

Под каждым новым ответом можно добровольно нажать «Полезно» или «Нужна
доработка». В локальную таблицу обратной связи при этом записываются только
случайный технический идентификатор ответа, выбранная оценка и время; текст
вопроса, ответа, истории и координаты не копируются. Оценка не запускает
обучение сама по себе. Полные правила приведены в
`BRAIN_V3_FEEDBACK_POLICY.md`.

Для подключения сайта доступен `POST /search`: он принимает `query` и возвращает не более пяти ссылок. Автоматическое выполнение найденного содержимого запрещено.
HTML-файл можно открыть напрямую из `web_client/index.html`, но API всё равно должен быть запущен.

В браузерном чате нет флажка поиска. В режиме `auto` сервер сам подключает
интернет для явно внешнего или меняющегося вопроса: например, про новости,
погоду, цену, расписание, актуальные сведения или по прямой просьбе «найди».
К явным правилам добавлен собственный обученный `internet-router-v1.0`: он
распознаёт и естественные формулировки вроде вопроса о результате вчерашнего
матча, но запускает поиск только при уверенности не ниже `0.90`. Обычные
вопросы по известным локальным темам не отправляются в сеть. Для
интернет-ответа берутся до трёх результатов и выдержки максимум из двух
страниц; известные официальные и профильные домены читаются раньше случайных
агрегаторов. Чат показывает один краткий проверяемый факт без URL. Ссылка на
ресурс выводится только по прямой просьбе, например «покажи источник» или «дай
ссылку». Страница не исполняется и её текст не становится инструкцией для
программы. Одна случайная общая фраза страницы не считается подтверждённым
фактом: если связи с вопросом недостаточно, чат честно попросит уточнение или
предложит отдельно показать найденные ссылки.

Дополнительно установлен `web-dialogue-policy-v1.0`. Он не отменяет эти
правила, а добавляет осторожный сигнал для естественных внешних формулировок,
которые старый router не распознал. На закрытом test он не дал ложных поисков;
из-за маленького синтетического набора его пороги намеренно высокие. Поэтому
любой положительный ответ всё равно проходит обычный контролируемый путь
поиска, а не превращается в самостоятельное выполнение страниц.

Для любого вопроса о погодных условиях чат использует структурированный
публичный источник Open-Meteo, поэтому возвращает числовые поля прогноза, а не
заголовок погодного сайта. Распознаются фразы о дожде, снеге, осадках,
температуре, ветре, влажности, давлении, видимости, восходе и закате — даже без
слова «погода», включая ясность и солнечность. Например, «Будет ли завтра дождь в Старом Осколе?» и «Какая
влажность завтра?» идут в тот же маршрут. Ответ содержит только запрошенный
показатель или краткую сводку; название источника и URL по умолчанию не
показываются.

Также можно спросить «Что надеть завтра в Минске?» или «В какой одежде идти
сейчас?». В ответе используются только температура, осадки и ветер
структурированного прогноза: подходящий слой одежды, зонт/непромокаемый верх
при осадках и предупреждение о сильном ветре. Это практическая погодная
подсказка, а не совет о здоровье или личном стиле.

Если город или село указаны в сообщении, он всегда имеет приоритет. Короткое
продолжение использует последнее место, которое пользователь явно назвал в этом
же локальном диалоге. Если места нет, при первом погодном вопросе браузер просит
разрешение на геолокацию и передаёт координаты только вместе с текущим запросом.
Координаты не записываются ни в SQLite, ни в `localStorage`, ни в текст ответа.
В памяти вкладки они переиспользуются для погодных запросов не дольше пяти минут,
после чего браузер запрашивает свежую позицию.
Если разрешение не выдано или сигнал недоступен, чат коротко просит назвать
населённый пункт вместо нерелевантного общего поиска.

После погодного прогноза в том же диалоге можно обычной фразой спросить о
дожде, снеге, осадках, температуре, ветре, тумане, грозе или времени начала и
окончания осадков. Например, «А со скольки до скольки будет дождь?» использует
город, день или разрешённую геолокацию текущего запроса и отвечает по часовому
прогнозу. Для будущих влажности, давления и видимости чат выбирает значение
около полудня и явно указывает это время, а не выдаёт произвольный «средний»
показатель за факт.

Вопросы «который час», «какая сегодня дата», «какой день недели», «какой
сейчас месяц» и «какое время года» отвечаются локально по часовому поясу
сервера `Europe/Minsk`. Для них не нужен интернет и геолокация браузера не
запрашивается.

Если нужно запустить сервер вручную без launcher-файлов, выполните:

```powershell
python -m uvicorn ai_core.api_server:app --host 127.0.0.1 --port 8000
```

Если в чате появляется ошибка соединения, проверьте, что окно `start_chat.bat` или
PowerShell с API всё ещё открыто. Индикатор в шапке страницы показывает состояние
подключения и готовность модели.
После перезапуска API клиент сначала проверяет соединение и загружает историю, а затем разблокирует форму. Для health, истории и ответа установлены таймауты, поэтому зависший локальный запрос не оставляет кнопку заблокированной навсегда.

Перед локальным release candidate пройдите
`LOCAL_RELEASE_MANUAL_CHECKLIST.md`. В нём есть отдельные безопасные пункты
для обычного разговора, web-ответов, погоды, геолокации, голоса и адаптивного
интерфейса.

Когда API запущен, выполните:

```powershell
python evaluation/run_evaluation.py
```

Для честной проверки активной веб-версии без локальной базы знаний:

```powershell
python evaluation/run_topic_evaluation.py --topic web
```

Для отдельного эксперимента с beam search:

python evaluation/run_topic_evaluation.py --topic web --decoding beam --beam-width 3
```

В отдельной оценке старой свободной генерации режим `sample` дал лучшее сходство, чем beam search. Это не меняет основной API: для него по умолчанию включён надёжный каталог целых ответов.

Скрипт отдельно показывает точность локального baseline, ответы режима `neural-only`, повторы и среднее полнотекстовое сходство с правильным ответом. Это позволяет не путать найденный в датасете ответ с результатом генерации модели и сравнивать разные токенизаторы.

```

Проверка использует новые сценарии из `training_data/web_followup_eval.jsonl`, не добавляет их в обучение и сравнивает продолжение с контекстом и без него. Подробный результат сохраняется в `WEB_FOLLOWUP_EVALUATION_REPORT.md`.

## Ограничение текущей версии

Основной режим состоит из `web-qa-intent-v2.0` и `web-dialogue-intent-v2.10`. Он поддерживает 32 ограниченных смысла по базовым HTML, CSS и JavaScript. Для LMS добавлен отдельный `lms-context-policy-v2.0`, который получает контекст через автоматический локальный индекс и прошёл строгий test `2812/2812` без неверных принятых ответов и без пересечения контекстов с train/validation. Неподдерживаемый или недостаточно уверенный вопрос получает просьбу уточнить, а не догадку.

Это ещё не универсальная разговорная модель и не обещание идеального ответа на произвольную тему. Надёжность достигается ограниченным каталогом полных ответов и контролем уверенности. Контролируемый интернет-поиск включается автоматически для внешних и меняющихся сведений; страницы не исполняются, а ответ опирается только на их проверяемые выдержки.

LMS-модель также не является универсальным собеседником. Автоматический индекс
отвечает только при выборе одного подтверждённого контекста. В приложенном
синтетическом наборе одна и та же формулировка может иметь разные проценты для
разных версий курса, поэтому без отличительной детали чат должен уточнить, а не
выдумывать число. Это сознательный безопасный этап после проблемы случайного
декодирования.

Старая `tiny-gru-bpe-web-v1.3-dialogue` сохранена как исследовательская свободная генерация. Она доступна только через `response_mode=experimental`, потому что её neural-only результат остаётся `0/28` точных ответов. Веб-интерфейс этот режим не включает.

Если в локальном датасете для одного точного вопроса есть несколько разных ответов, API возвращает источник `local-dataset-conflict` и просьбу проверить данные. Это защищает чат от случайного выбора неверного варианта.

## Контекст диалога

История текущего диалога сохраняется в SQLite. Надёжный веб-диалоговый слой
использует последний подтверждённый полный ответ как состояние. Автоматический
LMS-маршрут хранит отдельно только последний подтверждённый контекст и учитывает
до шести прошлых реплик пользователя при поиске новой записи. Ответы ассистента
не участвуют в поиске как доказательства. Контекст можно отключить через
`use_conversation_context=false` при прямом запросе к API.

## Диалоговое обучение

Надёжный follow-up обучается по `training_data/dialogue_curriculum.json` схемы 2. Ручные границы дополнены составными смысловыми структурами: действиями, объектами, зависимыми от состояния формулировками, контрастами и техническими маркерами декодера. Финальный checkpoint использовал 11 330 пар «реплика + состояние» и 924 validation-пары. Подробные метрики находятся в `RELIABLE_DIALOGUE_REPORT.md`.

Старые файлы `dialogue_examples.jsonl`, `web_dialogue_examples.jsonl` и `web_dialogue_examples_v2.jsonl` сохранены для воспроизводимости GRU-экспериментов. Отклонённый v2 подключается к старому обучению только явным флагом `--include-extended-web-dialogue`.

## Conversation-mind v2.0

Обычный чат использует локальный `conversation-mind-v2.0` раньше старого
разговорного fallback. Это не свободный посимвольный генератор: собственная
EmbeddingBag+MLP сеть выбирает план общения, а composer собирает краткий
читаемый ответ из контролируемых смысловых частей. Такой подход не даёт модели
вывести набор букв и не заставляет повторять небольшой архив готовых фраз.

Слой понимает приветствие, благодарность, разговор, уточнение, исправление,
поддержку, выбор, мнение, предпочтение и продолжение текущей беседы. Он хранит
текстовую историю в уже существующей локальной SQLite-памяти, не повторяет
недавний ответ дословно и не показывает ссылку без явной просьбы пользователя.
Погода, время, дата, новости, цены и другие проверяемые сведения не
перехватываются: они остаются у соответствующего локального или интернетного
маршрута.

Повторить воспроизводимое обучение после нового аудита можно так:

```powershell
.\.venv\Scripts\python.exe -m ai_core.conversation_mind_dataset --archive "C:\Users\KROLL\Downloads\Chat_AI_dataset_500000.zip" --output evaluation\results\conversation-mind-v2-data-audit-final
.\.venv\Scripts\python.exe -m ai_core.train_conversation_mind --archive "C:\Users\KROLL\Downloads\Chat_AI_dataset_500000.zip" --audit evaluation\results\conversation-mind-v2-data-audit-final\conversation_mind_data_audit.json --output model_artifacts\conversation_mind
.\.venv\Scripts\python.exe -m evaluation.evaluate_conversation_mind --output evaluation\results\conversation-mind-v2-acceptance-rerun
```

Подробные данные, границы и результаты находятся в
`CONVERSATION_MIND_TRAINING_REPORT.md`. Это более сильный локальный
разговорный слой, но не обещание человеческого сознания или универсального
знания: для следующего роста нужен новый разнообразный, согласованный и
лицензионно чистый разговорный набор, а не повтор одних и тех же строк.
