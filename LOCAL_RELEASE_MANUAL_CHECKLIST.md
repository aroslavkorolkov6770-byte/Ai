# Ручная приёмка локального чата до релиза

Статус: ожидает запуска локального API и действия пользователя в браузере.  
Дата создания: 2026-09-19.  
Публикация или отправка данных во внешние сервисы этим документом не разрешается.

## Как подготовить проверку

1. Запустите `start_chat.bat` двойным щелчком или в PowerShell выполните
   `./start_chat.ps1` из папки проекта.
2. Откройте `http://127.0.0.1:8000/` и дождитесь статуса готового подключения.
3. Для голосовой проверки используйте обычный современный браузер. Разрешение
   микрофона подтверждает только пользователь в системном окне браузера.
4. В этой таблице отмечайте `PASS`, `WARN` или `FAIL`, браузер и короткую
   наблюдаемую причину. Не вставляйте сюда личные сообщения из чата.

## Блок A — обычный разговор и текущий контекст

| Проверка | Действие | Ожидаемый результат | Итог |
| --- | --- | --- | --- |
| Приветствие | Написать «Привет». | Короткий естественный ответ без HTML/CSS/LMS. |  |
| Поддержка | Написать «Я сегодня устал после работы». | Спокойный ответ без поиска и без диагноза. |  |
| Личный совет | Написать «Как мне спокойно поговорить с другом после ссоры?». | Полезный следующий шаг, без ссылки и без ухода в поиск. |  |
| Контекст | Сначала написать «Мне важно, чтобы ответы были короткими», затем спросить совет. | Следующий ответ заметно компактнее; в нём нет дословного повтора настройки. |  |
| Отмена настройки | После прошлого пункта написать «Расскажи подробнее». | Новый запрос важнее старой краткости. |  |
| Follow-up | После разговора о работе и учёбе написать «Продолжим». | Ответ продолжает тему и не повторяет предыдущую реплику ассистента дословно. |  |
| Исправление | Написать «Ты не понял, я имел в виду другое». | Ассистент принимает уточнение, а не защищает старое предположение. |  |

## Блок B — интернет, дата и ссылки

| Проверка | Действие | Ожидаемый результат | Итог |
| --- | --- | --- | --- |
| Личная фраза с датой | Написать «Как ты считаешь, стоит ли мне сегодня поговорить с другом?». | Разговорный ответ без ненужной задержки поиска. |  |
| Свежий факт | Спросить о сегодняшней новости, цене или результате матча. | Автоматически используется web-маршрут; ответ не выглядит как заголовок поиска. |  |
| Ссылка по желанию | После web-вопроса написать «Покажи источник». | Ссылка показывается только после этой прямой просьбы. |  |
| Календарь | Спросить время, дату, день недели или время года. | Короткий локальный ответ без поиска. |  |
| Слабый источник | Задать редкий вопрос, для которого источники не дают фактов. | Честное уточнение вместо случайной выдержки или рекламной ссылки. |  |

## Что фиксировать после проверки

- Дата, браузер и версия браузера.
- Статус каждого пункта: `PASS`, `WARN` или `FAIL`.
- Только техническое описание сбоя: например, «голос не поддержан браузером».
- Нельзя записывать в этот отчёт координаты, аудио, ключи, личные сообщения
  пользователя или содержимое сторонних страниц.

Если найден `FAIL`, сначала сохраните его воспроизводимые технические шаги,
а затем исправляйте только подтверждённую причину. Не включайте новый decoder,
не обучайте веса и не публикуйте GitHub ради обхода одного дефекта.
