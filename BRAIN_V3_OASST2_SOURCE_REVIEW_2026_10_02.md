## Практическая пригодность

Это возможное продолжение уже известного источника для отдельного пилота.
Оно не доказывает закрытие нужных тем, тонов или целей общения. Доля новых
русских человеческих многоходовых диалогов после фильтров неизвестна.
Старые решения по другим источникам не пересматриваются этим документом.

Предположение о пересечении OASST1/OASST2 основано на общем издателе,
периоде сбора и формате; точное пересечение пока не посчитано. Требуется
сверить ID исходных деревьев и сообщений, а затем content exact/near и
закрытые evaluation-наборы. Одна только новая дата release не доказывает
новизну записи.

Особенно важно: текущий OASST1 адаптер выбирает split по
`SHA-256(source_id + tree_id)`. Если просто поменять source_id на OASST2,
один старый разговор может получить другую часть данных. Поэтому такая
замена адаптера не годится для нового импорта.

## Следующий технический шаг

1. Первичная фиксация asset выполнена по опубликованному [LFS pointer](https://huggingface.co/datasets/OpenAssistant/oasst2/raw/179dd21fc55192153d94adb0e0ce8f69e222bf75/2023-11-05_oasst2_ready.trees.jsonl.gz):
   `54 370 156` байт, SHA-256
   `7a886a16ccfc1173c4f00a6897523e3c95b2785a86ee44a18a98f4f2807ee29b`.
   Descriptor сохранён в
   `data/brain_v3/intake/openassistant-oasst2-source-review-v0.1.json`.
   Прочитаны только страницы описания и трёхстрочный pointer; сам gzip
   не скачан. При будущем intake нужно проверить его фактические bytes/hash.
2. Для первоначального изолированного пилота исключить **целые деревья**,
   присутствующие в исходном OASST1 intake. Это сохраняет прежние split и
   позволяет оценить прирост без повторного включения старых семей.
3. Принимать только явно `synthetic=false`, `deleted=false`,
   `review_result=true`, русский язык и корректные цепочки user/assistant.
   Неизвестные значения и модельное происхождение отправлять в отказ.
4. Сначала измерить выход фильтров и распад по длине/темам; не присваивать
   human-reviewed метки автоматически. Не переносить user_id и свободные
   служебные поля в обучение.
5. Проверить повторы и общие префиксы с active corpus и holdout. Все ветви
   новой семьи держать в одном split. Выделять только целые диалоги.
6. По реальному выходу сформировать небольшую стратифицированную выборку
   качества; решение о расширении принимать по разнообразию и связности,
   а не по исходному числу сообщений.

Пока этот документ не разрешает promotion или запуск обучения и не меняет
активный manifest. Если источник не даст достаточного нового разнообразия,
он не заменит другие способы заполнить смысловые дефициты.

## Подготовленный компонент исключения старых семейств

`ai_core/openassistant_family_guard.py` читает проверенный по bytes/SHA-256
исходный OASST1 gzip и строит в памяти общий для release namespace
`openassistant-message-tree-v1`. Он учитывает все старые деревья, включая
не прошедшие ранние фильтры, и не зависит от новой ветви или source_id.
Повтор tree ID, повреждённый архив и изменение файла во время чтения
останавливают расчёт. На диск исходные реплики и user ID не копируются.

Локальный запуск подтвердил `10 364` старых семейства. Hash проверенного
архива: `2a9a8fd343e9b28e04a895a669d3253f82d93e9c174d440199ae19d5fafbdff7`.
Hash упорядоченного индекса отпечатков:
`670fa9a3872215f81c674e0cda594b067a5b0cfb5c599a8e647dd1a7afa09d3c`.
Индекс не заменяет сравнение текстовых exact/near-повторов и holdout;
будущий OASST2 adapter должен вызывать его до отбора ветвей.
